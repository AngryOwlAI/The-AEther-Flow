## 8. Implementation Order Rules

The default implementation order is:

```text
P0 → P1 → P2 → P3 → P4 → P5 → P6 → P7 → P8 → P9 → P10 → P11 → P12 → P13 → P14 → P15 → P16 → P17 → P18 → P19
```

1. If P0 proves a later tracked state already completed a phase, mark it implemented by later tracked state and continue.
2. If P1 finds registry inconsistency, complete P1-T02 before P2.
3. If P2 produces a hard obstruction that invalidates certificate algebra assumptions, route to P3 repair before continuing.
4. If P2 produces a result needing immediate Refuter or smuggling audit, complete those before any project-system phase.
5. If validation fails in any phase, route exactly one repair task before continuing.
6. If a protected human gate is required, do not simulate approval. Record the human-gated route and select an allowed non-promotional next step.
7. If route-orbit detection triggers freeze review, do not continue orbiting the same burden without freeze evaluation.

# Narrow Theorem Task Template

This template is for future bounded theorem or precondition packets that sit
below matter-coupling derivation, source-law adoption, and downstream GR
promotion authority.

The template is a control artifact. It does not prove a theorem, adopt an
object, authorize matter coupling, authorize stress-energy semantics, authorize
matter action, authorize Einstein equations, authorize benchmark promotion, or
close a derivation.

## Use Conditions

Use this template when a selector or handoff names a narrow theorem or
precondition route, including:

- no-target certificate hygiene;
- `RR_E` separation preservation under explicit source certificates;
- finite/local stability of scoped evidence or preconditions;
- source-side equivalence-class reasoning under explicit source certificates;
- coupling-law or detector-semantics target formalization only, without
  adoption.

Do not use this template for direct universal matter-coupling derivation unless
separate tracked authority has already satisfied the P11 matter-coupling
moratorium prerequisites.

## Required Task Fields

Every future task using this template must fill the fields below.

### Exact Theorem Question

State the theorem or precondition question in one sentence.

Required:

- name the exact object, route, or certificate family under study;
- state whether the packet is proving a theorem, formalizing a target, mapping
  prerequisites, or recording a scoped obstruction;
- state what the theorem must not be read as establishing.

### Assumptions

List every source-side assumption.

Required:

- source objects, domains, maps, equivalence relations, selectors, certificate
  families, or witness families used;
- existing scoped evidence or preconditions used only as evidence;
- regularity, locality, finite-variation, invariance, transport, or
  factorization assumptions;
- all fail-closed defaults when an assumption is absent.

### Source Certificates Required

List the exact certificates required before the theorem can be attempted.

Required:

- certificate names or placeholders;
- authority source path or planned source path;
- whether each certificate is negative hygiene, positive evidence,
  source-extension data, canonical-ontology candidate, or adopted authority;
- what fails closed if the certificate is missing.

### Source Certificate Checklist Receipt

For any theorem packet that relies on source transport, source invariance, or
source factorization certificates, include a receipt against
`research_control/design/source_certificate_algebra_checklist.md`.

Required:

- state whether each required certificate is valid, missing, malformed, or
  fail-closed;
- state whether detector semantics, target metric data, or benchmark behavior
  were excluded from certificate premises;
- name any obstruction emitted by a missing or malformed certificate;
- state that passing the checklist is workflow evidence only and not proof
  authority, source-law adoption, matter semantics, detector semantics, matter
  coupling, Einstein equations, benchmark promotion, or completed derivation.

### `RR_E` Handling

State how `RR_E` records are preserved, transported, factored, compared, or
left separated.

Required:

- exact `RR_E` records or classes being handled;
- source transport, source invariance, or source factorization certificates
  required for any identification;
- explicit statement that `RR_E` is not collapsed by detector semantics,
  `g_eff`, benchmark behavior, convenience, or notation;
- fail-closed result if certificates are absent.

### No-Target Hygiene

State which no-target or no-process-authority certificates appear.

Required:

- no-target-topology, no-target-atlas, no-target-metric, no-detector,
  no-stress-energy, no-action, no-benchmark, and no-process-authority
  certificate status when relevant;
- explicit statement that negative certificates block target imports only;
- explicit statement that negative certificates do not supply positive matter
  semantics, detector semantics, stress-energy semantics, matter action, or
  coupling laws.

### Accepted Evidence And Preconditions Used

List accepted scoped evidence or preconditions used by the packet.

Required:

- exact object name;
- current tracked status;
- authority path;
- scope qualifier;
- forbidden overreads preserved.

Accepted evidence or preconditions must not be rendered as adopted source law,
adopted matter semantics, adopted detector semantics, adopted coupling law, or
derived matter coupling unless a separate Gate Chair authority says so.

### Forbidden Downstream Overreads

Every task must preserve these blocked readings unless a separate protected
authority explicitly changes them:

- source-law adoption;
- `PositiveMSProfile_v1` adoption;
- `RR_ETransportCompletenessOrInvarianceLaw_v1` adoption;
- matter-semantics adoption;
- detector-semantics adoption;
- coupling-law adoption;
- matter-coupling derivation or adoption;
- stress-energy semantics;
- stress-energy tensor;
- matter action;
- `MetricData(E)` adoption;
- `g_eff` scope expansion;
- Einstein equations;
- benchmark promotion;
- completed derivation;
- future source-extension impossibility;
- project-wide no-go conclusion beyond the scoped obstruction.

### Stress And Refuter Requirements

State the required audit or stress before any stronger route.

Required:

- hidden target-import audit;
- certificate-smuggling audit;
- finite/local variation stress when relevant;
- `RR_E` non-collapse stress when relevant;
- no-target certificate overread test;
- fail-closed behavior when a stress fails.

### Adoption Status After Theorem

State the maximum possible status after the theorem completes.

Allowed status values:

- `draft/control`;
- `proposal-only`;
- `source-extension data`;
- `canonical-ontology candidate`;
- `adopted`;
- `rejected`;
- `human-gated`.

Unless the task is explicitly a protected Gate Chair packet, the default
post-theorem status is `draft/control` or `proposal-only`.

### Selector And Gate Requirements

State what must happen after the theorem packet.

Required:

- whether a selector must choose the next route;
- whether a smuggling audit or refuter stress must occur;
- whether a Gate Chair packet is lawful;
- what exact protected authority would be requested if a gate is needed;
- what route follows if the result is only a scoped obstruction.

stress-energy semantics, matter action, coupling law, matter coupling,
Einstein equations, benchmark promotion, or completed derivation.

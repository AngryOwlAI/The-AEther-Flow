# No-Leap Route Rule

## Purpose

This control note formalizes the v13 P3-T01 no-leap route rule for
high-risk matter-coupling-chain objects.

The rule prevents a local construction, source-purity audit, Refuter stress
survival, or scoped Gate Chair evidence/precondition acceptance from being
overread as matter-semantics adoption, detector-semantics adoption,
coupling-law adoption, matter-coupling derivation, Einstein-equation
derivation, benchmark promotion, or completed derivation.

## Authority Status

This is a project-control route rule. It is not a physics theorem, not a
canonical ontology edit, not source-extension adoption, not Gate Chair
adoption authority, and not proof authority for any GR claim.

The rule applies to future high-risk matter-coupling-chain routing unless a
later tracked control source supersedes it. If this note conflicts with
`research_control/program_state.yaml`, the latest handoff named there, a
protected Gate Chair decision, or the Distance-to-GR ledger, the higher
tracked authority source governs.

## Rule Statement

For a high-risk object in the matter-coupling chain, the following results do
not authorize downstream adoption or promotion:

- construction pass;
- source-purity audit pass;
- Refuter stress survival;
- scoped Gate Chair evidence/precondition acceptance.

These results authorize only the next bounded route named by a tracked
selector, or a protected Gate Chair decision if exact human authority exists
and the decision scope explicitly grants that authority.

## Forbidden Leap Targets

The results listed above must not be read as authorization for:

- matter-semantics adoption;
- detector-semantics adoption;
- coupling-law adoption;
- matter-coupling derivation;
- matter-coupling adoption;
- stress-energy semantics;
- stress-energy tensor construction;
- matter-action import;
- `MetricData(E)` adoption;
- `g_eff` adoption or scope expansion;
- Einstein-equation derivation;
- exact-GR benchmark route or promotion;
- benchmark Gate Chair closure;
- completed derivation;
- future source-extension impossibility;
- global theory rejection.

## Required Selector Classification

A post-result selector packet over a high-risk matter-coupling-chain object
must record:

| Field | Requirement |
| --- | --- |
| Object | Name the object, source path, and current status vocabulary. |
| Prior result | Classify the immediately preceding result as construction, audit, stress, or scoped gate acceptance. |
| Allowed next route | Name exactly one next bounded route, or state that a protected Gate Chair decision is required. |
| Forbidden overreads | List the downstream claims blocked by the no-leap rule. |
| Gate status | State whether exact protected human authority exists, and quote the authorized scope if it does. |
| Proof authority | State that commits, generated registries, validators, role names, and derivative artifacts are not scientific proof authority. |

## Route Examples

| Prior result | Allowed reading | Allowed next route | Forbidden reading |
| --- | --- | --- | --- |
| Candidate object constructed | A proposal-only or draft/control object exists under the packet scope. | Smuggling audit or another tracked source-purity route. | The object is adopted, source-law status is granted, or matter coupling is derived. |
| Source-purity audit passed | The object appears source-pure as written under the audit scope. | Refuter stress or a selector that explicitly names a bounded next route. | The audit pass is proof authority, or the object becomes adopted source-extension data. |
| Refuter stress survived | The stress result did not defeat the object under the declared tests. | Post-stress selector or protected Gate Chair review if the plan requires it. | Stress survival implies matter semantics, detector semantics, coupling law, or Einstein equations. |
| Scoped Gate Chair evidence/precondition accepted | A bounded evidence/precondition status is accepted only under the quoted protected scope. | Selector classification, boundary synchronization, or the next specifically authorized protected decision. | Scoped acceptance is law adoption, matter-semantics adoption, coupling-law adoption, or benchmark promotion. |
| Protected Gate Chair adoption decision with exact scope | Only the named object and status inside the decision scope are authorized. | The next downstream route named by the decision or selector. | Adoption of adjacent objects, unscoped promotion, matter coupling, Einstein equations, benchmark closure, or completed derivation unless explicitly authorized. |

## Forbidden Overread Table

| Triggering result | Forbidden overread | Correct control reading |
| --- | --- | --- |
| Construction pass | A constructed object is adopted or canonical. | The object is available for the next bounded audit or stress route only. |
| Source-purity audit pass | Source-pure means source-law adoption. | Audit passed under declared tests; stress and gate obligations remain. |
| Refuter stress survival | Stress survival proves the object or unlocks downstream physics. | Stress survival is a routed control result and requires selector classification. |
| Scoped Gate Chair evidence/precondition acceptance | Scoped acceptance adopts `SourceMatterSemanticsAdoptionReadinessLaw_v1` as law. | Acceptance is limited to the quoted evidence/precondition scope. |
| Scoped Gate Chair evidence/precondition acceptance | Scoped acceptance adopts matter semantics or detector semantics. | Matter and detector semantics remain separate blocked targets. |
| Scoped Gate Chair evidence/precondition acceptance | Scoped acceptance derives matter coupling or a coupling law. | Coupling-law and matter-coupling routes remain blocked pending a separate tracked packet. |
| Any local high-risk pass | Local success establishes global impossibility of future source extension failure. | Local success is not a no-go theorem and does not close continuation. |
| Validator, generated registry, generated wiki, handoff, role, commit, or checkpoint success | Operational success is scientific proof authority. | Operational success is transaction evidence only. |

## P3-T01 Satisfaction Criteria

P3-T01 is satisfied when:

- this rule exists as a registered project-control source;
- route examples distinguish construction, audit, stress, scoped gate, and
  protected adoption cases;
- the forbidden overread table blocks matter-semantics, detector-semantics,
  coupling-law, matter-coupling, Einstein-equation, benchmark, completed
  derivation, future-impossibility, and global-rejection leaps;
- the completion handoff routes only to v13 P3-T02 selector checklist update.

This note does not implement P3-T02, P3-T03, P3-T04, P4, or later v13 tasks.

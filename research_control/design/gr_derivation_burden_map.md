# GR Derivation Burden Map

## Purpose

This control note separates derivation planning from agent-routing planning.
It is not a physics proof and does not promote any ontology, metric, matter
coupling, Einstein-equation, benchmark, or Gate Chair claim.

The project target remains conservative: recover ordinary GR or an exact-GR
benchmark from source-side AEther / AEther-flow structure without importing the
target metric or benchmark behavior by hand. This map records the dependency
chain future physics AgentJobs must name when they are routed.

Reference: Project review memo. (2026, June 17). *Review project goal
06-17-2026* [Internal project review].

## Future AgentJob Contract

Every future physics AgentJob after `2026-06-17T15:46:25Z` must declare:

- `target_derivation_milestone`: one roadmap milestone.
- `milestone_burden`: the exact burden the task attempts to discharge.

If an AgentJob cannot name the milestone it advances, it should not be routed
as physics derivation work. It may still be documentation, validation,
methodology, or project-system work.

## Mathematical Payload Rule

Every future physics completion after `2026-06-17T15:46:25Z` must name at least
one `new_mathematical_payload` item. Accepted payload families include a new
definition, lemma, theorem, finite model, countermodel, explicit witness,
obstruction, dependency-map update, finite toy model target, source-extension
classification, packet selection, or one of the established role-specific
payload types.

## Freeze Criteria

A repeated-burden or scoped-obstruction completion must evaluate whether the
current route should be frozen. For the present response-localization line, the
candidate freeze label is:

`NDCL-RESP-LC-SELECTOR-UNDERDETERMINATION`

This label means the current source tuple does not determine response sign,
normalization, or token semantics under the no-target-import rules. It does
not reject the entire ontology, prove future source-extension impossibility, or
promote a global no-go theorem.

## Source Extension Category

Source extension is a controlled category, not an informal escape hatch. Future
selector decisions may route:

- `source_extension_candidate`
- `source_extension_smuggling_audit`
- `source_extension_refuter_stress`
- `source_extension_human_gate`
- `source_extension_adopted_or_rejected`

Each source-extension decision must classify whether the proposal is a
derivation from current ontology, a conservative definitional extension, a new
ontology primitive, or a forbidden target-GR import disguised as ontology.

## Finite Toy Model Target

Before a full source-to-GR derivation is claimed, the project should attempt a
finite toy source-to-response target. The toy target must specify:

- a finite source set;
- source-local readout syntax;
- source-side orientation, normalization, and token candidates;
- an induced response relation;
- a toy effective metric or distance-form analogue; and
- invariance checks under relabeling and finite variation.

The toy target is draft/control scaffolding only. It cannot by itself establish
`g_eff`, matter coupling, Einstein equations, or benchmark recovery.

\section{Conservativity Classification}

\begin{lemma}[Forgetful conservativity over the old source language]
Let \(\varphi\) be a statement written only in the old source language
of \(\SX\), with no occurrence of \(O_X^R\), \(N_X^R\), \(K_X^R\),
\(o_X^R\), \(\nu_X^R\), or \(\kappa_X^R\). Evaluating \(\varphi\) on
\(\Splus\) by first applying \(F_X\) gives exactly the same truth
condition as evaluating \(\varphi\) on \(\SX\).
\end{lemma}

\begin{proof}
By definition \(F_X(\Splus)=\SX\). Since \(\varphi\) contains only old
source-language symbols, none of its terms or predicates can inspect
\(\XiR\). Therefore the extension changes no old-language statement
under the forgetful reduct. This is a definitional conservativity
statement only. It does not prove that \(\XiR\) is determined by
\(\SX\).
\end{proof}

\begin{proposition}[Import classification]
The packet is classified as a conservative definitional extension
candidate relative to the expanded signature \((\SX,\XiR)\). Relative
to the current retained tuple alone, it is not a derivation. If later
treated as canonical ontology, it would become a source-extension
adoption question and would require the normal audit, Refuter, and
human-gated authority sequence.
\end{proposition}

\begin{proof}
The construction introduces explicit new candidate source-side symbols
and a forgetful reduct. That makes old-language statements conservative
under \(F_X\), but it does not supply a theorem deriving those new
symbols from \(\SX\). The adoption status therefore cannot be decided
by this packet. It must be audited for hidden imports and overread
before any stronger status is considered.
\end{proof}

# Director Decision Record DDR-20260617-009

## Decision

Route `RT-20260617-009` to one task-overlay
`project-control-maintainer@0.1.0` AgentJob,
`AJ-RT-20260617-009-001`.

## Basis

The user explicitly rejected the current GitHub-facing Markdown style and
requested a complete reset of the root `github-facing/*.md` documents. The
request identifies a project-system problem: script-enforced Markdown layout
has been treated as content law even though the Documentation Curator should
decide what each reader-facing file says and how it is organized.

The durable repair must therefore do two things in one bounded transaction.
First, the GitHub-facing contract and audit must be narrowed so they preserve
source binding, source-material coverage, synchronized Mermaid blocks, stale
path detection, and unsafe authority-claim guards without enforcing one fixed
reader section template. Second, every root GitHub-facing explainer must be
rewritten from the registered source specs and source bundles as a
subject-first explanation for humans and external AI on GitHub.

The human gate is satisfied by the user's explicit instruction to remove the
old GitHub-facing Markdown content, start from scratch, use the
Documentation Curator teaching-loop approach, keep scripts advisory, and use
Mermaid/workflow explanations where appropriate.

## Claim Boundary

Allowed:

- rewrite the GitHub-facing explainer contract so script checks are guidance
  for content shape rather than canonical law;
- adjust `audit_documentation_surfaces.py` and focused tests so hard failures
  cover source binding, related HTML, generated-noncanonical authority status,
  source-material coverage, synchronized source Mermaid blocks, renderer-only
  headings, stale references, and unsafe authority or physics-promotion
  phrasing;
- downgrade rigid section-name and workflow-step-template checks to warnings
  or guidance;
- replace all root `github-facing/*.md` documents with richer source-backed
  subject-first explanations;
- use Mermaid diagrams in GitHub-facing Markdown where source-backed and safe;
- use Student/Teacher-style reader questions and source-bound answers as
  curated explanatory synthesis; and
- refresh registries and generated memory/wiki outputs through bootstrap.

Forbidden:

- canonical ontology edit;
- physics benchmark promotion;
- Gate Chair verdict;
- science draft edit;
- generated HTML as independent authority;
- generated GitHub-facing Markdown as independent authority;
- Teaching Q&A packets as canonical authority;
- broad role, schema, routing, or validator changes outside the
  GitHub-facing Markdown contract correction;
- generated wiki hand edits;
- direct HTML-only edits; and
- physics claim promotion.

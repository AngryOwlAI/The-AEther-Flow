## Evidence and boundary

- P2-T03 completed with PASS at commit
  `47d643ad558a459bf58f9eea6db53eeeb12422fd`.
- The worktree was clean and local `main` was three commits ahead of
  `origin/main` before the first P2-T04 write.
- The v19 plan names P2-T04, this role, the three skill contracts, the new
  policy, and a focused test requirement; no human gate is required.
- The active role registry row remains unchanged. Its validator labels stay
  auditable as obligation declarations and do not create independent command

The plan's planned source list does not name a test path, but its required
validation explicitly requires a test that parses skill command blocks or
obligation IDs. This overlay authorizes only
`tests/test_validation_obligation_resolution.py` for that purpose.

The first broader post-write suite proved that refreshing the three registered
skill hashes invalidated 124 historical memory-preflight checks because the
validator treated mutable skill contracts as immutable sources. A nonmutating
probe that added only the three skill object IDs to
`MUTABLE_MEMORY_PREFLIGHT_SOURCE_OBJECT_IDS` reduced the error count from 124
to zero. This decision therefore also authorizes only that three-entry update
in `scripts/research_control/validate_research_control.py` and the directly
coupled stale-hash fixture in `tests/test_research_control.py`. The fixture now
uses a synthetic immutable object for stale-hash rejection and separately
proves that a historical skill-contract hash is allowed. Rewriting historical
receipts or retaining stale registry hashes is forbidden.

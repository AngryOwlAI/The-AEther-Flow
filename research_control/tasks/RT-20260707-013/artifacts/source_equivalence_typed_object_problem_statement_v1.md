# Source-Equivalence Typed-Object Problem Statement v1

## 1. Control Status

This artifact implements v18 `P2-T01`. It is a draft/control problem
statement for a typed source-equivalence object. It translates the prior
record-local `EqSrc` theorem candidate into a typed target for later schema,
definition, audit, and stress packets.

It does not discharge general `EqSrc`, adopt `RetainH`, adopt `GenH`, adopt a
source law, edit canonical ontology, adopt `MetricData(E)`, expand `g_eff`,
derive matter coupling, derive Einstein equations, promote a benchmark, issue
a Gate Chair verdict, authorize external outreach, or claim completed
derivation.

## 2. Prior Record-Local Theorem Target

The prior theorem candidate defines a record-local datum
`E_rec = (Obj_rec, Inv_rec, Cmp_rec, Ann, Infl)` and relation `EqSrc_rec`.
Inside one declared finite source-record orbit, explicitly supplied
source-side relabeling maps witness reflexivity, symmetry, and transitivity
when all identity, inverse, and composition checks are listed and remain
source-side.

The theorem candidate is therefore local to a declared finite orbit. It is not
family-level source equivalence.

## 3. Named Obstruction

The live obstruction is:

`OB-P6T02-GENERAL-EQSRC-FAMILY-CLOSURE-MISSING`

The obstruction says that the record-local theorem does not supply the family
domain, invariant ledger, comparison rule, identity/inverse/composition
closure, negative-control retention, or proof that broadening avoids `RetainH`
and `GenH`. It is a scoped obstruction to overreading the theorem candidate,
not a global no-go theorem.

## 4. Record-Local Orbit Versus Source Family

The record-local orbit is a finite packet whose objects and relabeling maps
are explicitly listed. Success in that orbit proves only that the supplied
maps satisfy the equivalence-relation proof obligations inside that finite
packet.

A source family is a typed class of source objects and source-side morphisms
with rules for admissible variation, retention, generation, comparison, and
negative controls. A family-level `EqSrc` result needs closure under those
rules. It cannot inherit closure merely from one finite record-local orbit.

## 5. Candidate Typed Object

Define the next target as a draft/control typed object:

`TypedSourceEquivalenceObject_v1`

The object has the following required slots.

| Slot | Required Meaning |
| --- | --- |
| `object_domain` | Declared source-side objects or object families to be compared. |
| `morphism_family` | Source-side admissible relabelings or morphisms between objects. |
| `invariant_ledger` | Source-only invariants used by the comparison. |
| `comparison_rule` | A source-only rule returning `EqSrc`, `not_EqSrc`, or `Block`. |
| `annotation_ledger` | Source path, object id, hash, rule scope, dependency, and proxy-exclusion annotations for every comparison step. |
| `influence_ledger` | Forbidden-channel and proxy influence edges that are blocked rather than silently ignored. |
| `identity_witnesses` | Source-side identity maps for every object in scope. |
| `inverse_witnesses` | Source-side inverse data or an explicit countermodel slot. |
| `composition_witnesses` | Source-side composition data or an explicit countermodel slot. |
| `negative_controls` | Source-side cases where the same rule returns `not_EqSrc` or `Block`. |
| `RetainH_boundary` | Conditions under which retention under an `H`-indexed operation is required. |
| `GenH_boundary` | Conditions under which an `H`-generated source family is required. |
| `freeze_boundary` | Exact repeated-burden or scoped-obstruction condition that freezes or redirects the route without global rejection. |

## 6. Objects, Morphisms, Ledgers, And Comparison

An object in `TypedSourceEquivalenceObject_v1` is source-side data. It is not a
target manifold, metric, detector protocol, benchmark branch, validation
status, role label, or handoff state.

A morphism is admissible only if it preserves declared source tokens,
source-side invariant entries, annotations, proxy exclusions, and influence
edges. Any needed target topology, target metric, proper time, detector
protocol, stress-energy semantics, matter action, benchmark behavior, or
authority status makes the comparison fail closed.

The invariant ledger must list each invariant and why it is source-side. The
comparison rule must be mechanically checkable from tracked sources and must
return `Block` for missing annotations, unmapped proxy use, changed influence
incidence, or target-side comparison.

Identities, inverses, and composition are not implicit. They must be supplied
as typed data, derived under source-only rules, or identified as the exact
missing slot.

## 7. Where RetainH Enters

`RetainH` enters only if the route asks whether source-record structure,
comparison status, certificate status, or invariant status is preserved under
an `H`-indexed retention operation.

For P2-T01, `RetainH` is a boundary condition and possible primitive
requirement. It is not adopted.

## 8. Where GenH Enters

`GenH` enters only if the route constructs, enumerates, or quantifies over an
`H`-generated source family.

For P2-T01, `GenH` is a boundary condition and possible primitive
requirement. It is not adopted.

## 9. Theorem Success

Theorem success for a later typed-object packet requires all of the following:

- A declared typed source family or explicitly bounded family fragment.
- Source-only objects and morphisms.
- A comparison rule that does not use target-side or authority-status proxies.
- Identity, inverse, and composition closure.
- Negative controls retained under the same comparison rule.
- Explicit `RetainH` and `GenH` disposition: not required for the theorem,
  required as named missing primitives, or supplied only by separately
  authorized source-side draft/control artifacts.
- Smuggling audit and Refuter stress remain future requirements before any
  downstream promotion.

## 10. Countermodel Success

Countermodel success requires a finite or symbolic source-side structure that
satisfies the declared typed inputs but fails at least one exact burden:

- identity closure,
- inverse closure,
- composition closure,
- invariant preservation,
- comparison-rule source purity,
- negative-control retention,
- `RetainH` independence,
- `GenH` independence, or
- fail-closed proxy/influence coverage.

The countermodel must identify the failed typed slot. It must not rely on a
target metric, target locality, benchmark behavior, detector protocol,
validation status, role status, handoff status, or other authority proxy.

## 11. Primitive Requirement Success

Primitive requirement success means the packet proves that a broader route
requires a named source-side primitive that is not supplied by current tracked
authority. For this P2 target, the likely primitive-requirement outcomes are:

- `RetainH_required`: an `H`-retention law is needed for preservation.
- `GenH_required`: an `H`-generator law is needed for family construction.
- `comparison_rule_required`: a more explicit source-only rule is needed.
- `invariant_ledger_required`: family-valid invariants are missing.
- `negative_control_required`: fail-closed controls do not survive broadening.

Such a result may route to a later definition-candidate, countermodel, audit,
or stress packet. It does not adopt the primitive.

## 12. Freeze

Freeze is lawful only if the typed-object route reaches a repeated unmet burden
or scoped obstruction with no new payload available inside the current
authority boundary. A freeze must name the exact typed slot that fails and
must preserve same-milestone continuation unless a protected human-gated route
is required.

Freeze does not mean global theory rejection, future source-extension
impossibility, benchmark failure, or completed derivation failure.

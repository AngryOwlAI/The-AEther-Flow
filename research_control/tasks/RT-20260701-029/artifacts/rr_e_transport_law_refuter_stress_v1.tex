\section{Stressed schema}

For a declared source object \(F:D_E\to X\) and a source-side
\(\RRE\)-variation pair \(\VarRR(r,r')\), the proposal-only schema permits
identification only by:
\[
\begin{array}{ll}
\text{transport branch} & \TrRR(r,r')\ \text{with source soundness for }F,\\
\text{invariance branch} & \InvRR(F;r,r'),\\
\text{factorization branch} & \FactRR(F)\ \text{and}\ F=\bar F\circ\pi_{\RRE},\\
\text{fail-closed branch} & \SepRR(r,r')\ \text{or obstruction}.
\end{array}
\]
The Refuter stress asks whether these branches collapse under missing
certificates, relabeling, declared-object changes, target-pressure, or
process-authority pressure.

\section{Stress cases}

\begin{stresscase}[Malformed, absent, or deleted certificates]
If \(\TrRR\), \(\InvRR\), or \(\FactRR\) is malformed, absent, or deleted,
the schema has no certificate-free identification branch. The result is
\(\SepRR(r,r')\) or obstruction. This is a fail-closed behavior, not a hidden
detector, metric, or benchmark repair.
\end{stresscase}

\begin{stresscase}[Transport relabeling with changed retained \(\RRE\)]
Suppose \(r,r'\) preserve non-\(\RRE\) support while changing retained
\(\RRE\) syntax. If a valid \(\TrRR(r,r')\) certificate plus source soundness
for \(F\) is supplied, the transport branch is lawful. Without that certificate
the schema preserves separation or obstruction. Thus relabeling does not
produce unrestricted \(\RRE\) irrelevance.
\end{stresscase}

\begin{stresscase}[Changing the declared source object]
An invariance certificate \(\InvRR(F;r,r')\) is indexed to the declared
source object \(F\). Replacing \(F\) by \(F'\) invalidates the certificate for
the new object unless a new source certificate is supplied. The invariance
branch is therefore object-relative and cannot be read as detector
indifference or empirical equivalence.
\end{stresscase}

\begin{stresscase}[Target, detector, and benchmark pressure]
Detector response, empirical calibration, target geometry, \(\MetricData(E)\),
\(\geff\), stress-energy, matter action, Einstein equations, and benchmark
behavior are not admissible \(\TrRR\), \(\InvRR\), or \(\FactRR\)
certificates. Pressure to use them returns obstruction under the schema's
source-only rules.
\end{stresscase}

\begin{stresscase}[Process-authority pressure]
Validator success, registry rows, generated derivatives, roles, approvals,
handoffs, checkpoints, commits, and local caches are not mathematical
certificates. They may record provenance or validation receipts, but they do
not repair a missing source certificate and do not promote the schema.
\end{stresscase}

\begin{theorem}[Fail-closed transport-law stress theorem]
For the proposal-only \(\LawRR\) schema as audited, every Refuter stress
branch either supplies an explicit source certificate \(\TrRR\),
\(\InvRR\), or \(\FactRR\) with the declared object \(F\), or it fails closed
to \(\SepRR(r,r')\) or obstruction. No stress branch lawfully imports detector
semantics, target metric data, \(\MetricData(E)\), \(\geff\), benchmark
behavior, process authority, or generated-derivative authority.
\end{theorem}

\begin{proof}
The audited schema enumerates exactly three identification branches and one
fail-closed branch. The three identification branches require source
certificates indexed to \(r,r'\) and, for invariance or soundness, to the
declared source object \(F\). Deleting, malformed, or changing those
certificates removes the branch. The schema does not contain any branch whose
premise is detector response, empirical calibration, target geometry,
\(\MetricData(E)\), \(\geff\), benchmark behavior, validation, registry
metadata, generated text, role authority, approval language, checkpoint state,
or commit state. Therefore the only possible outputs of the stress table are a
source-certificate identification or fail-closed separation/obstruction.
\end{proof}

\begin{lemma}[Declared-\(F\) locality]
\(\InvRR(F;r,r')\) cannot be transported to a changed object \(F'\) without a
new source-side invariance certificate for \(F'\).
\end{lemma}

\begin{proof}
The formalizer indexed the invariance branch by the declared object. Changing
the object changes the proposition whose equality must be proved. No source
rule in the proposal-only schema transfers the proof automatically.
\end{proof}

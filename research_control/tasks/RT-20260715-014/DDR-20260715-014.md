## Selected Role

Use one Project-Control Maintainer task overlay. It may edit only the Make
entry-point contract, contributor guidance, the new environment contract,
task-local evidence, control registries, and policy-generated derivatives.
Parent-child decomposition is not applicable because this is non-physics
project-system work.

## Claim Boundary

The packet may define one read-only environment prerequisite target, retain
the explicit setup target, and record Python and dependency fingerprints. It
must preserve CI provisioning, requirements files, `handoff-0740`, and the
ordinary EqSrc route. It may not implement P4-T01, change workflow behavior,
promote physics claims, or treat validation evidence as proof authority.

## Validation

PASS requires concise missing-interpreter and missing-dependency failures, a
clean setup-then-check fixture, no package-state mutation during validation,
no `pip install` in any Make validation plan, a deterministic environment
fingerprint, documentation-impact and research-control PASS, and a governed
checkpoint. Otherwise stop without committing invalid state.

## Outcome

The environment prerequisite now guards every public Make validation entry
point, emits deterministic interpreter and dependency identity, and never
installs packages. A clean CPython 3.12 fixture failed compactly before
provisioning, passed after explicit `setup-dev`, and retained the same package
state across validation. CI and requirements sources remain unchanged.

## Scope-alarm review

The functional patch reaches the plan's three named source surfaces: the
Makefile, contributor guidance, and one new control contract. The Makefile
change is approximately one hundred lines because the deterministic receipt
logic is self-contained and shared by all targets; no dependency, public
schema, validator source, test source, or architectural rewrite was added.
This is the smallest complete boundary that meets the plan's fail-fast and
reproducible-fingerprint obligations.

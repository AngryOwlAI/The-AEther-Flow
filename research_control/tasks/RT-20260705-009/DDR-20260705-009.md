# DDR-20260705-009

## Decision

Create one bounded `validator-engineer@0.2.0` task overlay for v16 P6-T02.
The task implements the P6-T01 selected target, `certificate record type and
validity predicate`, as a support-only Python typed algebraic spec plus
`unittest` coverage.

## Evidence

- `handoff-0581` requires one P6-T02 support-only executable certificate spec.
- The v16 plan permits Python typed algebraic spec plus unit tests.
- P6-T01 selected the certificate record type and validity predicate as the
  smallest reusable kernel for P4 positive instances, P4 negative examples,
  and the P5 missing-composition obstruction.
- The P4 schema defines valid, missing, malformed, target-import,
  detector-semantics, process-authority, and fail-closed statuses.

## Rationale

The Validator Engineer role fits because the payload is deterministic
support-only tooling. A task overlay is used to prevent overread: this packet
may author a local pilot spec and tests, but it may not promote the pilot into
standing repository validators or scientific proof authority. That integration
decision belongs to P6-T03.

The selected implementation is deliberately finite and record-oriented. It
models the schema vocabulary, checks domain/codomain membership for witness
tables, rejects target/process imports, rejects scoped evidence used as a
certificate slot, and returns fail-closed results for negative records.

# Director Decision Record: DDR-20260614-281

## Decision

Select `validator-engineer@0.2.0` for one bounded P7-T03 graph freshness
validation packet.

## Basis

`handoff-0313` requires one P7-T03 validator packet to add freshness validation
for generated dependency graph artifacts. The P7-T03 plan requires a check that
the generated JSON, Markdown, and DOT graph artifacts are fresh relative to
tracked source registries and completions, with a fresh pass and deliberate
stale failure.

The selected role is appropriate because the packet adds deterministic validator
behavior and focused regression tests. It has no physics milestone and cannot
turn generated graph output into physics evidence, proof authority,
claim-promotion authority, or control authority.

## Scope

Allowed:

- Add `render_dependency_graph.py --check`.
- Compare generated JSON, Markdown, and DOT artifact content against current
  tracked-state renders.
- Add focused tests proving fresh artifacts pass and deliberately stale
  artifacts fail.
- Regenerate graph artifacts after final tracked control state.
- Update control registries, task records, documentation-impact receipt,
  `program_state.yaml`, and `handoff-0314`.

Blocked:

- canonical ontology edit
- source-law adoption
- `MetricData(E)` adoption
- `g_eff` adoption or scope expansion
- coupling-law adoption
- matter-coupling derivation or adoption
- stress-energy semantics
- stress-energy tensor
- matter action
- detector semantics
- Einstein equations
- benchmark promotion
- completed derivation
- treating graph output or graph freshness as physics evidence
- treating generated graph artifacts as control authority
- Distance-to-GR ledger change
- Gate Chair verdict or protected evidence-status change

## Result

The selected packet installs content-based graph freshness validation, exercises

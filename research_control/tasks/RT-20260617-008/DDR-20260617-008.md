## Basis

The user requested implementation of the visual and workflow-step
recommendations after reviewing `project-system-improvement-explainer.html`.
The request affects the Documentation Curator output system, tracked HTML
explainer set, GitHub-facing Markdown derivative set, and project-system
contracts that keep those surfaces synchronized.

The durable implementation is not a direct HTML-only edit. It must inspect the
registered source specs, decide where a workflow-step section is appropriate,
update source-spec guidance, update derivative HTML and GitHub-facing
Markdown, and add contract/audit support so future workflow/control pages do
not drift again.

The human gate is satisfied by the user's explicit instruction to implement the
recommendations across the project system, documentation system, HTML explainer
system, and GitHub-facing Markdown system.

## Claim Boundary

Allowed:

- add contract language requiring GitHub-facing workflow-step sections when
  the paired source spec declares `workflow_step_inspector`;
- add deterministic audit coverage for that conditional Markdown section;
- update source specs with page-specific workflow-step inspector basis;
- update tracked HTML derivatives from the source specs;
- update GitHub-facing Markdown derivatives with source-backed workflow-step
  sections where appropriate;
- record a curator audit explaining which pages did and did not receive the
  section; and
- refresh registries and generated memory/wiki outputs through bootstrap.

Forbidden:

- canonical ontology edit;
- physics benchmark promotion;
- Gate Chair verdict;
- science draft authority expansion;
- generated HTML as independent authority;
- generated GitHub-facing Markdown as independent authority;
- conceptual pages made to look like active workflow gates when the source spec
  does not support that reading;
- validator change outside the workflow-step Markdown synchronization guard;
- routing behavior change; and
- physics claim promotion.

## Decision

Select one bounded `theoretical-continuation-selector@0.1.0` task overlay for
v16 P6-T01 formalization scope selection.

## Evidence

- `handoff-0580` requires one P6-T01 support-only formalization scope
  selector.
- The v16 plan requires exactly one target, a justified toolchain, and a
  handoff to P6-T02.
- P4 already supplies positive transport, invariance, factorization, and
  negative certificate instances.
- P5-T03 proves only conditional transitivity under a supplied valid compatible
  composition certificate and records the missing-composite obstruction.
- P6-T02 explicitly asks an executable certificate evaluator to model record
  fields, valid/missing/malformed states, domain/codomain matching,
  no-target guard, target-import rejection, process-authority rejection,
  scoped-evidence failure, expected equivalence, and fail-closed results.

## Rationale

The selected target is `certificate record type and validity predicate`. It is
the smallest kernel that all later executable checks need. It can consume P4
positive and negative instances, explain the P5 missing-composition
obstruction, and support future P14 target-import fixtures without claiming
proof authority.

The selected toolchain is a Python typed algebraic spec plus `unittest`
coverage. This matches local deterministic validation practice, adds no new
dependency, and can express finite/local records and fail-closed outcomes in
one bounded P6-T02 task.

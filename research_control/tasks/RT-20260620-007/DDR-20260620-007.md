# DDR-20260620-007: Checkpoint Tracked Local Staging Fix

## Decision

Route one bounded Validator Engineer AgentJob to repair
`scripts/research_control/checkpoint_research_transaction.py` so checkpointing
stages tracked `.local` generated derivatives while continuing to exclude
untracked `.local` scratch output.

## Rationale

The prior checkpoint left
`.local/content_semantics/markdown/md-schema-agent-job-schema.txt` modified
after commit. The file was not omitted because it was invalid or outside the
generated-output model. It was omitted because checkpoint staging used a broad
`path.startswith(".local/")` filter. That filter was correct for untracked
local scratch caches but too broad for files Git already tracks.

The smallest correct fix is to distinguish tracked generated `.local` files
from untracked scratch output. Validation may continue to treat `.local` as
retrieval-only authority, while checkpoint staging must commit tracked
generated derivatives that are already part of the repository state.

## Claim Boundary

This decision authorizes only checkpoint staging behavior for tracked `.local`
files, focused regression tests, the pending tracked semantic derivative,
bounded task records, control registry rows, documentation-impact receipt, and
generated memory refresh outputs. It does not authorize canonical ontology
edits, benchmark promotion, physics claim promotion, generated-output authority
expansion, permanent role registration, untracked `.local` staging, or creation
of a physics research artifact.

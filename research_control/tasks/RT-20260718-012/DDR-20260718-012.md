## Supersession decision

The user plan is narrower and newer authority for P0-T03 execution-policy
behavior. It supersedes the v20 card's assumptions that validation failure,
dirty state, repeated fingerprints, no progress, or task boundaries always
cause immediate termination. Under v3 those findings first enter a distinct
safe authorized recovery route when one exists.

The supersession does not broaden task-specific goals. `single_objective`
remains the default and P0-T04 is outside this transaction. Only an original
user goal explicitly initialized as `multi_step` may cross among its listed,
dependency-ready work items.

tests and the task-local validator, not separate authority-bearing jobs.

## Scope alarm resolution

The work necessarily exceeds the ordinary three-file and one-hundred-line
alarms because the existing contract is deliberately split across two skills,
one reference schema, one executable helper, tests, and governed control
evidence. A partial patch would create incompatible launcher, worker, or state
semantics. The boundary remains exactly those five runtime/test files, one
task-local policy/scenario/validator packet, standard control records,
registries, and policy-generated derivatives.

## Claim and safety boundary

The new route selector chooses only between the already governed
`continue-research` and `improve-project-system` skills. It grants neither
skill new permissions. It cannot push, publish, install plugins, weaken
validation, steal leases, rerun consumed work, expand goal scope, modify
canonical ontology, grant Gate Chair authority, or treat worker prose as
evidence.

No physics source, scientific status, Distance-to-GR row, program state,
ordinary handoff, or completed P0-T02 artifact changes.

# DDR-20260801-004 — Repair validation runtime and integrate the revised soul

## Current objective

Integrate the exact human-authored `SOUL.md` revision and repair the concrete
Project Control Validation timeout without weakening its semantics. Two causes
are already reproduced: the six research-control wrapper modules fail because
the source inventory remained sealed at 149 tests after a 150th test was added,
and live validation repeatedly reparses the same tracked YAML thousands of
times. A process-scoped read cache reduced the measured validation pass from
more than seven minutes to about 56 seconds with zero errors.

## Authority surfaces read

The revised repository soul, root and research-control agent instructions,
`improve-project-system`, `user-modified-project`, the Project-System Director
and Validator Engineer contracts, task and AgentJob schemas, `handoff-0934`,
current program state, the registered `SOUL.md` source row, validation scripts,
wrapper shard inventory, focused tests, project-change classifier, signal
state, and hosted-run evidence were inspected.

## Source-backed resolution

Keep every validator and test enabled. Add a cache whose lifetime is one
explicit full-validation invocation and whose file identity includes stat data,
so fixture mutations cannot reuse stale parses. Reseal the wrapper inventory to
the observed 150-test source and add one focused cache-lifetime regression.
Routine memory bootstrap will integrate the revised canonical soul into its
registry hash and generated derivatives without editing generated files by hand.

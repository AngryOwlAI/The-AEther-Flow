\section{Stress Lemmas}

\begin{lemma}[Invalid source-readout branches fail closed]
Missing source records, malformed certificates, ambiguous readout attempts,
target imports, empirical detector substitutions, proper-time substitutions,
downstream matter-coupling imports, and process-authority substitutions do
not repair or extend \(\ReadoutSrc(\EStar)\). They map to \(\BottomSrc\).
\end{lemma}

\begin{proof}
Those branches are exactly the branches named by \(\FailR(\EStar)\). The
candidate does not define a recovery rule that can use detector protocols,
proper time, target geometry, benchmark behavior, stress-energy semantics,
matter action, Einstein-equation premises, validators, registries, roles,
handoffs, generated derivatives, local caches, checkpoints, commits, or file
order as source premises. Therefore the attempted substitution blocks rather
than supplying a positive readout value.
\end{proof}

\begin{lemma}[Finite certified relabeling preserves the listed witness]
Any finite source relabeling that preserves the three readable records, their
source certificates, and their readout-token assignments preserves the
P5-T04 finite witness.
\end{lemma}

\begin{proof}
The non-bottom graph entries are explicitly finite:
\[
  s_0\mapsto \rho^R_0,\quad
  s_1\mapsto \rho^R_1,\quad
  s_{01}\mapsto \rho^R_{01}.
\]
If the perturbation preserves the certified records and these graph entries,
the readout witness remains the same source-side finite graph up to relabeling.
If the perturbation deletes a record or certificate, creates ambiguity, or
imports target or process authority, the first lemma applies instead.
\end{proof}

\begin{lemma}[Compatibility loss is an integration pressure, not readout collapse]
Failure of limited compatibility with \(K_{E_{\ast}}\) blocks immediate
integration into the existing source-side coupling-law candidate, but it does
not by itself collapse the finite source readout map.
\end{lemma}

\begin{proof}
The source readout map is defined on \(\ReadableSrc(\EStar)\) with values in
\(\TokR(\EStar)\). Projection-level compatibility with \(K_{E_{\ast}}\) is an
additional integration statement. Removing that statement leaves a selector
or repair obligation for P5-T07; it does not remove the three non-bottom
source readout assignments.
\end{proof}

\begin{lemma}[Process authority cannot repair or promote the candidate]
Validation success, registry metadata, role identity, handoff state,
approvals, commits, generated derivatives, local caches, and file order
cannot provide source records, source tokens, certificates, detector
semantics, source detector/readout adoption, or matter coupling.
\end{lemma}

\begin{proof}
Those objects are provenance and process-control evidence. None is an element
of \(\SMScope(\EStar)\), \(\ReadableSrc(\EStar)\), \(\TokR(\EStar)\),
\(\CertR(\EStar)\), or \(\FailR(\EStar)\). Treating them as mathematical or
physical premises would change the candidate into an authority-status rule,
which the P5-T04 candidate and P5-T05 audit both forbid.
\end{proof}

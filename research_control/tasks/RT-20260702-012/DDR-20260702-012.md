# DDR-20260702-012: v14 P7-T01 Frontier Inventory Schema Reconciliation

## Decision

Route one bounded P7-T01 `frontier_theorem_inventory_schema_packet` to
`documentation-curator@2.0.0` through a task overlay.

## Basis

`handoff-0464` requires one bounded v14 P7-T01 frontier theorem inventory
schema reconciliation packet before inventory refresh implementation or
downstream physics routes. The v14 plan requires the existing schema to be
reused if sufficient and updated only for gaps.

The existing schema at
`research_control/design/frontier_theorem_inventory_schema_v1.md` already
defines a source-backed non-authoritative inventory control surface. It lacked
explicit v14 fields for milestone, object type, authority level, definitions
introduced, theorem-like claims, audits, stress results, Gate Chair results,
fail-closed branches, known obstructions, forbidden overread, downstream
blocked targets, next theorem needed, three-tier classification, and linter
status. P7-T01 is the narrow schema reconciliation packet for those gaps.

## Selected Role

`documentation-curator@2.0.0` is selected because the deliverable is a
registered Markdown documentation/control schema update and receipt. No physics
role or Gate Chair verdict is required.

## Scope

The AgentJob may update
`research_control/design/frontier_theorem_inventory_schema_v1.md`, create
task-local receipts, update live research-control state, update registry rows,
and regenerate derived memory/wiki/index artifacts.

It must not populate the inventory, add theorem interpretations, update public
surfaces, edit generated HTML, or change validator behavior.

## Claim Boundary

This packet reconciles schema fields only. It must preserve:

- no canonical ontology edit;
- no source-law adoption;
- no `RR_ETransportCompletenessOrInvarianceLaw_v1` adoption;
- no `PositiveMSProfile_v1` adoption;
- no `SourceMatterSemanticsAdoptionReadinessLaw_v1` law adoption;
- no `MetricData(E)` adoption;
- no `g_eff` scope expansion;
- no coupling-law adoption;
- no matter-semantics adoption;
- no detector-semantics adoption;
- no matter-coupling derivation or adoption;
- no stress-energy semantics;
- no matter action;
- no Einstein equations;
- no benchmark promotion;

\section{Theorem Statement}

\begin{theorem}[NarrowMSCertEq\_v1]
Under the assumptions above,
\[
  A_{\mathrm{src}} \EqMS B_{\mathrm{src}}.
\]
The equivalence holds only inside the declared source-side certificate scope.
It is not detector equivalence, physical matter equivalence, stress-energy
equivalence, matter-action equivalence, coupling-law equivalence, empirical
equivalence, benchmark equivalence, matter-coupling derivation, or source-law
adoption.
\end{theorem}

\begin{proof}
The P2-T02 manifest defines \(A_{\mathrm{src}}\EqMS B_{\mathrm{src}}\) to mean
that at least one permitted explicit source certificate exists, \(\CNTI\)
passes, declared-object indexing is consistent, and all fail-closed branches
remain inactive.

There are three certificate cases.

\emph{Transport case.} If \(\CTr(A,B)\) is supplied, it transports the declared
source labels, guards, and record indices of \(A_{\mathrm{src}}\) into those of
\(B_{\mathrm{src}}\). By the no-target and declared-object assumptions, this
transport does not depend on a target atlas, target metric, detector semantics,
benchmark behavior, or process authority. Therefore the transport case
satisfies the certificate clause in the definition of \(\EqMS\).

\emph{Invariance case.} If \(\CInv(A,B)\) is supplied, the relevant labels,
guards, and response-token relations are invariant under the declared
source-side relabeling or admissible source variation. Since \(\CNTI\) passes
and no fail-closed branch is active, the invariance case satisfies the
certificate clause in the definition of \(\EqMS\).

\emph{Factorization case.} If \(\CFact(A,B;F)\) is supplied, the proposed
equivalence factors through the declared source object \(F\) and preserves the
object-indexed \(\RREObj(F)\) boundary. By declared-object consistency, the
factorization object is the same object required by the certificate. By
\(\CNTI\), the factorization is source-side and does not import target or
process authority. Therefore the factorization case satisfies the certificate
clause in the definition of \(\EqMS\).

In each permitted case, the definition of \(\EqMS\) is satisfied. Hence
\(A_{\mathrm{src}}\EqMS B_{\mathrm{src}}\) follows inside the declared
source-side certificate scope.
\end{proof}

\section{Fail-Closed Branches}

\begin{proposition}[Certificate-gap fail-closed branch]
If none of \(\CTr(A,B)\), \(\CInv(A,B)\), or \(\CFact(A,B;F)\) is explicitly
supplied, then \(A_{\mathrm{src}}\EqMS B_{\mathrm{src}}\) is not derived under
the current premises. The branch status is
\[
  \texttt{certificate\_gap\_obstruction}
\]
for any concrete instantiation that tries to use scoped evidence/preconditions
as a certificate substitute.
\end{proposition}

\begin{proof}
The definition of \(\EqMS\) requires at least one explicit source transport,
invariance, or factorization certificate. If no such certificate is supplied,
the required existential certificate condition is false. Therefore the
equivalence is not derived. \(RR_E\) separation remains preserved unless a
later packet supplies a valid declared-object certificate.
\end{proof}

\begin{proposition}[Malformed or imported certificate fail-closed branch]
If the supplied certificate is malformed, object-mismatched, target-importing,
detector-semantic, benchmark-dependent, process-authority dependent, or uses
scoped evidence status as adoption, then \(A_{\mathrm{src}}\EqMS
B_{\mathrm{src}}\) is not derived under the current premises.
\end{proposition}

\begin{proof}
Each listed defect violates a required clause of the P2-T02 manifest:
certificate validity, declared-object consistency, \(\CNTI\), or inactive
fail-closed branches. Since \(\EqMS\) is defined only when all those clauses
hold, the defective branch cannot establish \(\EqMS\). The result is a named
fail-closed obstruction, not a detector-semantic repair and not a target-metric
repair.
\end{proof}

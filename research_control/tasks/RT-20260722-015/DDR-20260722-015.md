## Claim Boundary

After three consecutive completed project-system tasks, a prospective
ordinary research handoff must select a dependency-ready physics-bearing task
or carry an exact exception receipt showing every dependency-ready scientific
route is blocked by a tracked control failure. Exception evidence is
repository-relative, regular, hash-bound, and class-limited. The ordinary
research handoff remains route authority; a sidecar cannot replace it.

The activation task is not retroactively evaluated by the guard it creates.
Project-system work never earns physics credit. The packet may not change
science sources, the Distance-to-GR ledger, ontology, candidate status,
theorem truth, or protected authority.

## Validation

Completion requires positive and negative fixtures below and above the
threshold, physics-bearing selection, missing and malformed receipts,
partial blocked-route evidence, valid all-blocked evidence, human-gated
blocking, stale hashes, and sidecar-substitution rejection. It also requires
focused tests, documentation and claim gates, research-control and memory
validation, and one governed checkpoint.

Stop if an exception can proceed without all ready science being accounted
for, if a sidecar becomes route authority, if system work receives scientific
credit, if historical records are invalidated, if an edit escapes the
allowlist, or if a required validation or checkpoint fails.

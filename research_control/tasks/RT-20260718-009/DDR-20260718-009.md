# DDR-20260718-009: Make relay scheduling horizons unlimited by default

## Current Objective

Emit `continue-research-goal.v2` records in which omitted
`max_continue_passes` and `deadline_at` values are independently represented
as JSON `null`. Retain exact finite v1 read and validation behavior without
migrating or rewriting the retained local record.

## Evidence and Diagnosis

`RT-20260715-013` enabled the production profile but recorded finite launcher
guards as mandatory. The current helper emits only v1 records, requires both
finite CLI values, and unconditionally evaluates both scheduling stops. The
user has explicitly replaced only that finite-default policy.

The narrow implementation is a v2 schema with version-aware initial guard
hashing. V1 continues to hash its original `guards` object and use its
top-level finite deadline fallback. V2 includes top-level `deadline_at` in the
effective guard value so nullable and amended scheduling guards remain
hash-linked.

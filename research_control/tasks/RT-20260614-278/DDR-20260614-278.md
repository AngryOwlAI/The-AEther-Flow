# Director Decision Record: DDR-20260614-278

## Decision

Select `validator-engineer@0.2.0` for one bounded P6-T04 validator-hardening
packet.

## Basis

`handoff-0310` requires one P6-T04 packet to add completion validator checks for
required future physics payload fields. The P6-T04 plan requires completions
governed by the mathematical decisiveness contract to carry concrete payload
metadata, while preserving historical compatibility and avoiding historical task
rewrites unless separately authorized.

The selected role is appropriate because the work is deterministic validator
hardening with focused regression fixtures. This packet has no physics milestone
and cannot promote validator pass status into physics evidence.

## Scope

Allowed:

- Add required-field validation for `mathematical_payload_manifest` items in
  `scripts/research_control/validate_research_control.py`.
- Require nonempty `payload_id`, `payload_type`, `object_name`, `claim_status`,
  `source_path`, `burden_effect`, and `summary` for future mathematically
  decisive physics completions.
- Add focused regression tests for missing required fields, Candidate
  Constructor result enforcement, and repeated-burden freeze plus route-cycle
  enforcement.
- Update control registries, task records, documentation-impact receipt,
  `program_state.yaml`, and `handoff-0311`.

Blocked:

- canonical ontology edit
- source-law adoption
- `MetricData(E)` adoption
- `g_eff` adoption or scope expansion
- coupling-law adoption
- matter-coupling derivation or adoption
- stress-energy semantics
- stress-energy tensor
- matter action
- detector semantics
- Einstein equations
- benchmark promotion
- completed derivation
- historical task rewrite
- treating validator checks as physics evidence
- Distance-to-GR ledger change
- Gate Chair verdict or protected evidence-status change

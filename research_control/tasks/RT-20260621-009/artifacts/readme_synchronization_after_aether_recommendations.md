# README Synchronization After AEther Recommendations

## Analysis

The AEther recommendations implementation completed through Phase 9. A targeted
README scan showed that lower-level documentation already mentioned the
mathematical-decisiveness schema and metrics script, but the root README and
`research_control/README.md` still described only the older
Distance-to-GR payload requirement.

## Changes Made

- `README.md` now summarizes the mathematical-decisiveness completion contract
  and states that the metrics report is an AI-system diagnostic rather than
  physics evidence.
- `research_control/README.md` now has a dedicated Mathematical Decisiveness
  Contract section pointing to the contract, schema, template, Candidate
  Constructor result rule, and metrics script.

## Boundary

This packet changes front-door project-control explanation only. It does not
change validator behavior, schema behavior, role authority, skill contracts,
science sources, canonical ontology, source-law adoption status, `M_src`,
`g_eff`, matter coupling, Einstein equations, benchmark status, or Gate Chair
authority.

## Generated Systems

The wiki notes, local Obsidian vault, memory index, generated registries, and
source hashes are refreshed through the project-memory scripts. Generated
surfaces remain derivative retrieval support and do not become independent
authority.

## Historical Receipt Hash Refresh

Because `README.md` and `research_control/README.md` are registered source
objects, refreshing `MARKDOWN_SOURCE_REGISTRY.csv` changes the current source
hashes for `MD-README` and `MD-README-RESEARCH-CONTROL`. The research-control
validator compares historical memory-preflight receipts against the current
registry row. Following the existing project pattern, this packet mechanically
refreshes only those historical `source_hash` receipt values. It does not
change historical objectives, decisions, outputs, verdicts, role authority, or
claim boundaries.

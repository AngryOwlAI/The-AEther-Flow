# Director Decision Record: DDR-20260614-275

## Decision

Select `project-control-maintainer@0.2.0` for one bounded P6-T01
payload-density metrics design packet.

## Basis

`handoff-0307` requires one P6-T01 project-system metrics packet to define
payload-density metrics and warning thresholds. The v11 implementation plan
requires a metrics design artifact, a handoff to P6-T02, clear separation
between operational validation and scientific progress, no physics claims, and
machine-computable definitions from completion receipts and registries.

The selected role is project-control maintenance because this packet defines a
control contract for future metrics implementation. It does not implement
`report_physics_progress_metrics.py` and has no physics milestone.

## Scope

Allowed:

- Create one registered control Markdown design artifact for P6-T01.
- Define required payload-density and route-orbit diagnostics.
- Define advisory warning thresholds.
- Define the P6-T02 implementation contract.
- Update control registries, task records, documentation-impact receipt,
  `program_state.yaml`, and `handoff-0308`.

Blocked:

- implementation of P6-T02 script changes
- implementation of P6-T03 continue-research warning surfacing
- canonical ontology edit
- source-law adoption
- `MetricData(E)` adoption
- `g_eff` adoption or scope expansion
- coupling-law adoption
- matter-coupling derivation or adoption
- stress-energy semantics
- stress-energy tensor
- matter action
- detector semantics
- Einstein equations
- benchmark promotion
- completed derivation
- making diagnostics hard gates
- treating workflow metrics as physics evidence

## Result

The selected packet defines all P6-T01 metrics and warning thresholds in a
registered control artifact and routes the next legal continue-research step to
P6-T02 implementation.

Phase 3A Research-Control Operation

Research-Agent Workflow

A source-first operating map for routing physics continuation and project-system improvement through one bounded AgentJob, role constraints, checks, completion evidence, and human gates.

Operating Discipline, Not Proof Engine

The research-agent system makes theoretical work auditable. It turns requests into bounded transactions whose sources, role limits, write paths, and outcomes can be inspected later.

This generated noncanonical reader surface explains workflow operation. It does not change routing behavior, role authority, validator requirements, write permissions, claim boundaries, or physics status.

Two Lanes, One Boundary Rule

Physics Continuation

Use this lane for derivation work, candidate construction, refutation, audit, theoretical packet selection, or scientific handoff. Source: .codex/skills/continue-research/SKILL.md.

Boundary: continuation may construct or test draft/control material, but it does not promote claims without the required gates.

Project-System Improvement

Use this lane for documentation drift, validators, role or schema maintenance, memory tooling, workflow clarification, and public explainer packets. Source: .codex/skills/improve-project-system/SKILL.md.

Boundary: project-system work improves operation and documentation without changing physics status or canonical science sources.

Request To One Bounded AgentJob

Inspect

Read README.md, AGENTS.md, scoped guidance, active task state, and relevant registries before choosing a route.

Preflight

Use memory queries to locate prior context, then verify any influential hit against canonical files or registry rows.

Route

Classify the request or resolve tracked state, then choose continuation or project-system improvement.

Bind

Create or reuse exactly one AgentJob and bind it to an execution-role record.

Execute

Read and write only the allowed paths. Preserve forbidden paths, source classes, and claim boundaries.

Check

Run the required repository checks for the selected lane and transaction type.

Complete

Record outputs, command evidence, remaining limits, and next recommendation.

Handoff

When needed, name the next route precisely instead of expanding the completed job.

Memory Finds Sources, Sources Decide

Memory preflight is mandatory navigation for current routing and AgentJob creation. It can identify relevant objects, prior rollouts, or old surfaces, but it cannot override tracked source files.

Correct Use

Use a memory hit to decide which canonical Markdown file, TeX source, schema, skill contract, or registry row to inspect next.

Unsafe Use

Do not treat Obsidian notes, wiki notes, semantic extracts, `.local` files, or the memory index as authority.

Receipt

New jobs preserve the preflight commands, returned object IDs, canonical inspections, source registries, paths, and hashes.

When The Workflow Must Stop

  • A required write path is outside the AgentJob allowlist.
  • The work would edit canonical ontology, benchmark, or science-draft sources without the required gate.
  • The work would change role, schema, routing, validator, permission, or checkpoint behavior without a matching project-system packet.
  • A generated output, memory hit, or check result is being treated as authority.
  • The request honestly needs more than one AgentJob.

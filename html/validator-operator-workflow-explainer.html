Phase 4C - contributor/operator guide

Validator And Operator Workflow

Choose repository checks from the changed authority surface. Refresh generated derivatives through bootstrap, review publication pages with evidence, check project-system receipts, run research-control gates for control state, and treat PASS as bounded mechanical evidence.

This page explains Existing command selection, evidence paths, screenshot QA, and PASS-result limits.
It does not change Validator behavior, command semantics, role authority, schemas, routing, or checkpoint gates.
It cannot prove Scientific truth, ontology adoption, benchmark promotion, completed derivation, or publication taste.
operator decision

Start From The Change Type

The correct command set comes from what changed, not from habit. A small Markdown-only update, a governed public HTML page, a project-system AgentJob, and a validator script change carry different evidence burdens.

Memory or registry source Run bootstrap, then validate-only. Generated derivatives are refreshed by script.
Publication page Run publication checks and keep desktop/mobile screenshots under task artifacts.
Project-system AgentJob Classify, resolve, check emitted signals, document impact, and run control gates.
Research-control state Validate the tracked control spine and add --check-diff for write boundaries.
Scripts or tests Run targeted or full unit tests based on blast radius.

bootstrap discipline

Bootstrap Is A Refresh; Validate-Only Is A Check

Use bootstrap after source changes

Run bootstrap after changing registered Markdown, TeX, source specs, registry rows, or source material that feeds wiki notes, content semantics, Obsidian mirrors, file registries, object relationships, or memory-index state.

Use validate-only for read-only review

Validate-only checks the current generated state without writing. It is useful for final review, but it cannot refresh stale derivatives after a source change.

How to interpret stale local retrieval warnings
`.local`, Obsidian, semantic, and memory-index warnings are retrieval-layer warnings. They do not override tracked source files, registry rows, or research-control records unless a validator reports a hard failure.
project and control gates

When Extra Gates Are Required

1
Classify the live diff. classify_project_changes.py --json identifies documentation-impact and project-system reason codes.
2
For state-changing project-system jobs, write the receipt. research_control/tasks/<task_id>/documentation_impact.yaml must cover source paths, generated derivatives, reason codes, registries, and commands.
3
For research-control state, run control checks. Use the base research-control checker and add --check-diff when the live diff must be compared against allowed writes.
4
For tooling changes, run tests. Full test discovery is appropriate when the change crosses project-control, research-control, memory, or explainer boundaries.
review evidence

Screenshots And Final Receipts

Tracked HTML needs visual evidence

Governed publication pages need desktop and mobile screenshots under the current task artifact directory. When using the Playwright wrapper, check command -v npx first; screenshots still remain task evidence, not source authority.

Final review needs paths, not vibes

  • Changed source paths.
  • Generated derivative paths.
  • Screenshot paths for tracked HTML.
  • Before/after review notes.
  • Validator command results and claim boundary.
troubleshooting

Common Failures

Symptom Likely Cause Correct Response
Orphan public page report A source spec, GitHub Markdown page, or HTML page exists without a publication brief registry row. Add or correct the governed brief, spec, output path, and registry row in one bounded packet.
Missing screenshot evidence The registry row points to desktop or mobile screenshot paths that do not exist. Capture screenshots into the current task artifact directory and keep the paths stable.
Documentation-impact path gap The receipt did not list a changed source path or generated derivative pattern. Update the receipt to cover the live diff; do not remove a real source change to satisfy the receipt.
Write-path boundary failure A changed path is outside the AgentJob allowlist or protected by role/source-class rules. Narrow the packet, adjust the authorized task if valid, or stop for human authorization.
Stale local retrieval warning Obsidian, semantic, or memory-index derivatives lag source state. Treat as retrieval-layer warning unless a validator makes it a hard failure; tracked files and registries remain authority.
PASS boundaries

What PASS Does And Does Not Mean

PASS means the deterministic checks run by that command accepted the current state. It is necessary evidence for governed work, but it is not independent authority.

Safe reading

The command's mechanical conditions passed for the current repository state. The result can support a bounded completion when paired with source paths, generated paths, evidence artifacts, and a claim boundary.

Unsafe reading

PASS proves scientific truth, approves ontology, promotes the benchmark, certifies editorial quality, changes command behavior, or gives generated documentation independent authority.

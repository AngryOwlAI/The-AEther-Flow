Technical Requirements For Reproducible Operation

Technical requirements make AEther-Flow operable: Codex app access for governed agent work, Python environment setup, dependency ledgers, repository-owned scripts, screenshot tooling, memory refresh commands, and managed PDF derivative paths.

This is a generated noncanonical reader surface. It does not change dependencies, validators, Makefile targets, command semantics, harness policy, role authority, routing behavior, checkpoint behavior, generated-output authority, or physics claim status.

Operating model

Tools answer capability; sources answer authority.

A reproducible operator needs to know which local tools are required, which repository source names the workflow, and which task evidence proves a specific transaction stayed inside its boundary. The technical requirement answers the first part only.

Capability

Can the local environment inspect, run, refresh, screenshot, or build the requested artifact?

Authority

Which registered source, registry row, role or skill contract, and AgentJob allowlist permits the action?

Evidence

Which completion record, artifact, screenshot, or check result shows what actually happened?

Tracked HTML and diagrams

The publication path is source-spec first.

Tracked HTML under html/ must come from a page brief and a source spec. It must be standalone, no-network, and readable without JavaScript. Diagram and screenshot tooling may be needed to produce evidence, but the rendered page cannot require remote fonts, remote CSS, external scripts, browser-side Mermaid execution, hosted comments, or network assets.

Failure boundaries

A working tool is not a permission grant.

Safe inference

The environment can run the command family named by the source, and the task packet records the evidence required by that workflow.

Unsafe inference

The tool exists, so the operator can edit authority surfaces, skip the AgentJob allowlist, or treat generated output as source truth.

Corrective rule: return to the source path, registry row, role or skill contract, AgentJob allowlist, completion evidence, and claim boundary. Local retrieval hits, screenshots, generated HTML, and test results can support the review; they cannot replace the authority chain.

Operator sequence

Use technical requirements in a source-first order.

Identify the work tier: inspection, governed agent work, Python check, memory refresh, HTML screenshot QA, PDF derivative, or tests.
Inspect the listed source path before running commands.
Confirm the current task or AgentJob allows the write path if any source changes are involved.
Run the narrow command family from the repository source.
Preserve output evidence in the task packet when the workflow requires it.
Treat generated outputs and .local surfaces as support, not authority.

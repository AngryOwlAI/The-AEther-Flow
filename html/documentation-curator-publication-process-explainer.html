Documentation Curator Publication Process

How AEther-Flow public pages are planned, briefed, written, reviewed, and checked without turning generated reader surfaces into authority.

Generated noncanonical reader surface. This page explains the active publication process; it does not change role authority, validator behavior, schemas, routing, checkpoint gates, source authority, generated-output authority, corpus-migration approval, or physics claim status.

Publication Lifecycle

Brief

Define subject, reader, reader job, document type, visual strategy, source basis, boundaries, acceptance criteria, and forbidden patterns.

Bind

Create a Markdown source spec that names the brief, output paths, source materials, claim boundary, and standalone HTML constraints.

Write

Author native GitHub Markdown and a single-file HTML derivative from the same source basis and authority boundary.

Inspect

Capture desktop and mobile screenshots for tracked HTML and record the visual result in task artifacts.

Review

Write a before/after artifact that names improvements, risks, source limits, and non-authority boundaries.

Check

Run publication checks, bootstrap refresh, documentation-impact validation, research-control validation, and diff checks.

Markdown And HTML May Diverge

Shared Contract

GitHub Markdown and tracked HTML share source basis, authority boundary, and core claims. Both must show source paths and generated noncanonical status.

Different Strengths

Markdown reads as a native technical article. HTML can use layout, tables, timelines, and responsive hierarchy while remaining readable without JavaScript.

Review Checklist

Brief and registry row

The brief and registries/PUBLICATION_BRIEF_REGISTRY.csv row agree on paths, sources, visual strategy, and migration status.

Source-visible outputs

Both public derivatives name every source path and state generated noncanonical status.

No-network HTML

The HTML file is standalone and avoids external scripts, remote fonts, browser-side Mermaid execution, and local bridge dependencies.

Screenshots

Desktop and mobile captures prove the tracked HTML is readable and responsive enough for review.

Before and after

The review artifact names what changed, what improved, and which risks remain.

Checks do not replace judgment

scripts/validate_publication_process.py catches mechanical failures and retired patterns; it does not certify taste by itself.

Do Not Migrate This Way

  • Do not revive Visual Atlas as the active process.
  • Do not use a topic registry as the public page creation path.
  • Do not restore teaching packets as active public-page source.
  • Do not force old universal section headings onto unrelated subjects.
  • Do not add diagrams because a script rewards diagrams.
  • Do not treat validator PASS as publication quality by itself.
  • Do not put source metadata before the subject and reader problem.
  • Do not treat generated HTML, Markdown, wiki notes, Obsidian notes, semantic extracts, or .local caches as authority.

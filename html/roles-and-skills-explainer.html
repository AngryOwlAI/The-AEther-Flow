Authority path

Read The Catalog As A Pointer, Not A Contract

The catalog helps a reader find the right source. It is not the source that grants current execution authority.

1 Registry

AGENT_ROLE_REGISTRY.csv gives current status, version, role kind, gate flag, and default validators.

2 Contract

The active role contract or skill contract defines the stable mission, permissions, and boundaries.

3 Execution Role

The task-local role record binds a role to exactly one AgentJob and records any overlay constraints.

4 AgentJob

The AgentJob allowlist is the practical read/write and output contract for the transaction.

5 Evidence

The claim boundary, completion record, and validators decide whether the transaction closed cleanly.

Historical contracts

Superseded Means Interpretable, Not Active

Why old versions stay registered

Historical tasks point to the role version they used. Superseded contracts remain readable so old execution records remain auditable.

The deciding signal is the registry status field. A public catalog cannot revive a superseded role.

Common superseded groups

  • documentation-curator@0.1.0 through documentation-curator@1.0.0
  • director-of-research@0.1.0
  • ontology-formalizer@0.1.0, candidate-constructor@0.1.0, refuter@0.1.0, and smuggling-auditor@0.1.0

Failure modes

The Catalog Must Not Become Authority

Safe Use

  • Use the page to locate active role rows and skill entry points.
  • Inspect source contracts before acting.
  • Read execution-role records and AgentJobs for current authority.
  • Treat validator PASS as configured-check success only.

Unsafe Use

  • Using a catalog row as current write permission.
  • Presenting superseded roles as active.
  • Letting a skill bypass the AgentJob allowlist.
  • Executing Gate Chair work without tracked approval.
  • Treating generated documentation as physics or control authority.

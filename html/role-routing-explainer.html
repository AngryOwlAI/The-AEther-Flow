Role Routing And Execution Contracts

A role contract is a template. The execution-role record and AgentJob allowlist decide what the current job may actually do.

This page explains role routing. It does not register roles, expand authority, change schemas, change routing behavior, change AgentJob allowlists, or authorize claim promotion.

Surfaces Routing Families Fields Errors Sources

Three Surfaces To Inspect

Registered Role

Stable versioned template in .agents/roles/ and registries/AGENT_ROLE_REGISTRY.csv.

Useful for role identity, status, default validators, and human-gate flags.

Execution-Role Record

Task-local role contract in the task roles/ file and ROLE_EXECUTION_REGISTRY.csv.

Defines registered-role use, overlay, or one-job provisional role.

AgentJob Allowlist

Executable contract for reads, writes, expected outputs, validators, source classes, and claim boundary.

This is the practical permission surface for one transaction.

Execution-Role Routing

registered_role

Use direct template fit when no authority delta is needed. It may not silently add permissions.

task_overlay

Use when the base role remains correct but needs task-specific constraints or bounded non-promotional adjustment.

one_job_provisional_role

Use for a temporary one-job identity. It expires after the AgentJob and is not reusable until registered.

Authority Fields

When a route is under review, the useful fields are concrete and mechanical.

  • authority_level
  • may_execute_autonomously
  • may_create_outputs
  • may_modify_sources
  • may_promote_claims
  • requires_human_gate
  • allowed_source_classes
  • forbidden_source_classes
  • default validators
  • current AgentJob write allowlist

Common Routing Errors

Unsafe

  • Using a role name as current write permission.
  • Treating a task overlay as a reusable role version.
  • Reusing a provisional role after its AgentJob expires.
  • Assuming parent-child synthesis creates child role records.
  • Treating validator PASS as physics proof.

Safe

Inspect the role registry, role contract, execution-role record, AgentJob, claim boundary, and completion evidence in that order. Protected authority remains protected unless a human-gated path explicitly opens it.

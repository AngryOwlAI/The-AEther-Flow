Phase 3 Research-Control Operation

Role Routing And Execution Contracts

A role name is not current job authority. Registered roles are templates, task overlays are one-job constrained adaptations, provisional roles expire, and the execution-role record plus AgentJob allowlist decide what one transaction may actually do.

Contract Stack

Registered Role Contract

Stable versioned template in .agents/roles/ and registries/AGENT_ROLE_REGISTRY.csv.

Boundary: no current write permission by itself.

Execution-Role Record

Task-local contract in registries/ROLE_EXECUTION_REGISTRY.csv and the task roles/ file.

Boundary: binds one AgentJob to exact role semantics.

AgentJob Allowlist

Executable read/write, output, validator, source-class, and claim-boundary contract.

Boundary: controls actual file access for that transaction.

Authority Fields To Inspect

Review authority_level, may_execute_autonomously, may_create_outputs, may_modify_sources, may_promote_claims, requires_human_gate, allowed and forbidden source classes, default validators, and the current AgentJob write allowlist.

The logical inspection order is role registry, role contract, execution-role record, AgentJob, claim boundary, and completion evidence.

Safe And Unsafe Summaries

Safe

Registered roles are templates; execution-role records and AgentJob allowlists define one-job authority; protected promotion remains human-gated.

Unsafe

A role name alone grants permission, a provisional role becomes reusable by habit, or a documentation page can register roles or promote claims.

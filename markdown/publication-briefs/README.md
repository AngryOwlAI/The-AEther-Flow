# Publication Briefs

Publication briefs are the active quality surface for migrated public
explainers. Write the brief before changing a source spec, GitHub-facing page,
or tracked HTML derivative.

Each brief must name the subject, reader, reader job, document type, reading
experience, narrative structure, visual strategy, source basis, authority
boundaries, output surfaces, acceptance criteria, and forbidden patterns.

Approved examples in this directory:

- `project-overview.publication-brief.md`
- `source-authority.publication-brief.md`

Rejected patterns:

- forcing every page into `What This Does`, `Why AEther Needs It`, and
  `System Map`;
- adding a diagram because a validator expects one;
- copying generated prose as if it were source content;
- opening with source metadata before the subject; and
- treating GitHub Markdown and HTML as if they must share identical headings.

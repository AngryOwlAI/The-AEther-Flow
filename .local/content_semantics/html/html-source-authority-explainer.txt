Source Authority And Generated Derivatives
The trust question in AEther-Flow is not which page is clearest. It is which source is allowed to define project state for the claim being made. Public HTML, GitHub-facing Markdown, wiki notes, semantic extracts, Obsidian mirrors, and local caches can help a reader navigate; they do not outrank registered sources.
Use generated surfaces for orientation, then follow their source paths. If a generated derivative and a registered source disagree, the source wins and the derivative needs repair.
Reader scope: source-authority orientation only. This page cannot change the hierarchy, replace a registry, promote ontology, certify a benchmark, issue a Gate Chair verdict, expand roles, or modify routing behavior.

Authority Ladder
Registered TeX
Defines physics and derivational claims within stated status.
Cannot bypass claim gates or workflow authority.
Registries
Define routing, provenance, generated-output tracking, memory metadata, and source hashes.
Cannot replace the source files they describe.
Registered Markdown
Defines guidance, source specs, briefs, roles, skills, schemas, and control notes.
Cannot promote physics claims outside its lane.
Generated Surfaces
GitHub Markdown, tracked HTML, wiki notes, indexes, and PDFs orient readers.
Cannot override canonical sources.
Local Retrieval
Semantic extracts, Obsidian mirrors, SQLite indexes, and `.local` caches accelerate search.
Cannot serve as tracked control state.
Source-To-Derivative Boundary
Physics status or derivation
Inspect registered TeX and claim-boundary rows first. Use public pages only to find the source lane.
Task or routing authority
Inspect `research_control/` records and control registries first. Use explainers to understand the workflow shape.
Public explainer content
Inspect the publication brief and Markdown source spec first. Use HTML and GitHub-facing Markdown as reader derivatives.
Memory lookup or freshness
Inspect registry rows and project-memory skill guidance first. Use local retrieval as a way to find likely paths.
Source-First Checklist
Name the question type.
Identify the source lane.
Inspect source file and registry row.
Use generated pages only for navigation.
Preserve exact qualifiers.
Failure Modes
Generated-page promotion
Treating a clear HTML page as if it can promote a physics claim.
Registry bypass
Treating a wiki note or semantic extract as if it can override a registry row.
Local-cache authority
Treating `.local` cache state as tracked control state.
Validator overread
Treating PASS as scientific truth, editorial quality, role authority, or generated-output authority.

Safe And Unsafe Summaries
Safe
Use generated and local surfaces to find the right source, then inspect the registered source file and registry row before citing, editing, or routing.
Unsafe
A generated page, wiki note, PDF, semantic extract, Obsidian mirror, or `.local` cache can override the authority hierarchy.

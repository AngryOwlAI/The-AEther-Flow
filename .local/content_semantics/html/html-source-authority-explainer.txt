Summary of Source Authority
Source authority is the repository rule for deciding which files can define project truth and which files are generated aids for reading, retrieval, validation, or publication. Its functionality is to rank registered TeX, format-specific registries, registered Markdown, generated HTML, generated wiki notes, PDFs, local Obsidian surfaces, and `.local` caches so contributors update canonical sources first and regenerate dependent artifacts afterward. This matters because many surfaces are polished, searchable, or easier to read than the source files, but convenience does not create independent authority. The model preserves scientific claim discipline, project-control provenance, and reproducible memory refreshes across a repository that intentionally generates many human-facing derivatives.

The ladder starts with registered TeX for science-bearing derivation and benchmark claims. Format-specific registries carry routing, provenance, generated-output, hash, and memory authority. Registered Markdown carries front-door guidance, agent instructions, project-control notes, and source specs. Generated HTML, GitHub-facing Markdown, wiki notes, PDFs, semantic extracts, and local vault entries help readers and agents navigate. The ladder is not about file prestige; it is about which artifact may define a claim and which artifact must point back to something stronger.

Format meaning depends on use case. `.tex` is science source. `.md` can be front-door guidance, control notes, or source specs. `.csv` is registry authority. `.yaml` records tasks, jobs, approvals, roles, completions, and handoffs. `.html`, `.pdf`, and `wiki/` are generated reading surfaces. `.meta.json` records generated registry metadata. `.sqlite`, semantic extracts, Obsidian vault files, and `.local` caches support retrieval. The safe edit pattern is source first, regenerate second, validate third.

Generated derivatives exist because humans and agents need readable and searchable views. HTML explainers visualize source specs, GitHub-facing Markdown orients repository readers, wiki notes summarize registry objects, PDFs provide human-reading TeX derivatives, and semantic extracts power retrieval. Their usefulness does not change authority. If a derivative is stale or misleading, the repair is to update the source spec, source file, or registry row, then regenerate and validate.
Local Retrieval
.codex/skills/obsidian-wiki/SKILL.md
.codex/skills/project-memory-system/SKILL.md
Local retrieval surfaces accelerate navigation on one machine. The Obsidian vault, semantic text extracts, SQLite memory index, browser previews, and scratch outputs can help an operator find context quickly. They are subordinate to tracked sources and registries, and many live under `.local`, which is intentionally not canonical. Retrieval should answer where to inspect next, not what the project has proven. The retrieval layer is best understood as an index into authority, not an alternative authority ladder with its own claim status.
Validation Evidence
.codex/skills/project-memory-system/SKILL.md
scripts/project_control/validate_documentation_impact.py
Validation evidence ties sources to derivatives. Hashes detect stale files, source-basis metadata ties HTML to specs, Mermaid parity checks diagrams, bootstrap refreshes generated registries and wiki notes, documentation-impact receipts account for source and derivative changes, and research-control validators check task boundaries. Evidence does not make every artifact authoritative; it proves the artifact follows its declared source relationship. A valid receipt should make the path from source edit to generated output visible enough that another operator can reproduce the check.

Workflow Step Inspector
Edit source
Edit the authoritative TeX, registry, or registered Markdown source first.
Register
Update the corresponding registry row and source hash when required.
Regenerate
Regenerate wiki, HTML, PDF, semantic, or local retrieval surfaces through approved tooling.
Bind metadata
Preserve source-basis metadata and visible source evidence in derivatives.
Validate
Validate source parity, hashes, generated-output bindings, and authority status.
Read safely
Use generated surfaces for reading and retrieval, not independent claims.
Local boundary
Treat `.local/` caches as scratch or machine-local retrieval aids.
Return
Return to the canonical source or registry before changing project knowledge.

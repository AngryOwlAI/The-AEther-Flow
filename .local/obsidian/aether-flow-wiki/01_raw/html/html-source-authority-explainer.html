Source Authority And Generated Derivatives

The central trust question is which source is allowed to define project state. Clarity, polish, and searchability are useful, but they do not outrank registered sources.

Authority Ladder

Registered TeX

Physics and derivational claims live here when the TeX source is registered for that lane.

Registries

Routing, provenance, generated-output tracking, and memory fields live in controlled CSV rows.

Registered Markdown

Guidance, roles, skills, source specs, briefs, and control notes define their declared lanes.

Generated pages

GitHub Markdown, HTML, wiki notes, and PDFs orient readers by pointing back to sources.

Local retrieval

Semantic extracts, Obsidian notes, and `.local` caches are convenience layers only.

How To Use A Generated Page

  1. Read it for orientation.
  2. Follow the visible source paths.
  3. Inspect the source file and registry row.
  4. Make changes only through the authorized workflow.
  5. Regenerate derivatives and validate.

Failure Modes

Do not cite this or any generated page as proof of ontology adoption, benchmark promotion, Gate Chair verdicts, role expansion, routing changes, validator authority, or generated-output authority. If a derivative disagrees with a registered source, the derivative is stale or wrong.

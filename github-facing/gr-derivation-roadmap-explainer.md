# GR Derivation Roadmap

The GR derivation roadmap is the project's control surface for the open
first-principles derivation problem. It names the sequence of burdens that
would have to be discharged before the project could move from AEther /
AEther-flow source structure to an exact-GR benchmark promotion. The practical
use of the roadmap is not to celebrate progress; it is to keep every burden,
status term, source-extension qualifier, freeze label, and human gate attached
to its proper evidential weight.

## Status Terms

The roadmap uses controlled status categories such as `not started`,
`draft object exists`, `constructive witness exists`, `blocked by missing
primitive`, `accepted`, `frozen negative`, and `human-gated`.

These terms are deliberately narrower than ordinary prose summaries. A
`draft object exists` row means there is a controlled object or interface to
audit. It does not mean the object has been adopted as ontology or used to
derive downstream GR structure. A `frozen negative` row means a specific route
is blocked or should not be repeated without redesign. It does not reject the
entire ontology or prove future source-extension impossibility.

## Future Physics Job Fields

Every future physics AgentJob after the roadmap activation must name:

- `target_derivation_milestone`: the milestone it attempts to advance.
- `milestone_burden`: the exact burden the task attempts to discharge.

Every future physics completion must also name a `new_mathematical_payload`.
Accepted payloads can include definitions, lemmas, theorems, finite models,
countermodels, explicit witnesses, obstructions, dependency-map updates,
finite toy targets, source-extension classifications, and packet selections.

These fields do not make a task successful. They make the task falsifiable and
auditable: a reader can ask which burden was attempted, what mathematical
payload was supplied, and which downstream claims remain blocked.

## Freeze Criteria

Freeze labels preserve negative information. For the response-localization
line, the candidate label `NDCL-RESP-LC-SELECTOR-UNDERDETERMINATION` means the
current source tuple does not determine response sign, normalization, or token
semantics under no-target-import rules.

That label is scoped. It does not reject the whole ontology. It does not prove
that future source extensions are impossible. It does not authorize a public
claim that AEther-Flow failed globally. It tells future agents and readers
which route should not be repeated without a new payload or redesign.

## What Validators Cannot Prove

Project validators are necessary because this repository is source-first and
agent-operated. They catch missing fields, allowlist drift, stale generated
surfaces, stranded signals, and authority-boundary violations.

They cannot prove that `g_eff` exists, that matter couples universally, that
Einstein equations have been derived, or that benchmark promotion is
authorized. Those require scientific source artifacts, audits, refutations,
and human gates where the control system says a gate is required.

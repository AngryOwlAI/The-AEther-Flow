# Claim Gates, Negative Results, And Freeze Criteria

AEther-Flow uses claim gates to keep research work honest. A proposal can be
useful, a stress test can fail, and a route can be frozen without any of those
events becoming a public physics verdict.

This page is a generated noncanonical reader surface. It explains the claim
control model, but it does not create a claim boundary, issue a Gate Chair
verdict, promote a benchmark, reject the global ontology, change role
authority, or supersede tracked source files.

## The Claim Lifecycle

| Lifecycle state | What it means | What it does not mean |
| --- | --- | --- |
| Proposal | A bounded packet names a possible construction, extension, selector, witness, audit, or review target. | The packet is accepted physics. |
| Audit | A source-side or smuggling review checks whether the packet imports target-GR structure, role authority, generated-output authority, or hidden assumptions. | The audited object is automatically adopted. |
| Refutation or stress test | A reviewer tries to break the construction, find nonuniqueness, expose fragility, or show an underdetermination. | The whole theory is rejected. |
| Completion | One AgentJob records outputs, validators, claim boundaries, and next-route evidence. | The completion proves a broader theorem unless a scientific artifact actually proves it. |
| Handoff | The next route is named for future work. | The next route is already executed. |
| Freeze | A repeated-burden or scoped-obstruction route is preserved so it is not repeated casually. | A global no-go theorem is established. |
| Human gate | A protected decision such as ontology adoption, source-extension adoption, benchmark promotion, or Gate Chair approval requires human-gated authority. | Validators or generated pages can auto-promote the claim. |

The control value is conservative: each state narrows what can be said. It
does not broaden claim authority.

## Negative Results Are Preserved Evidence

A negative result is not project failure. It is a source-backed record that a
specific route, source tuple, primitive, selector, or construction attempt did
not meet its burden.

The repository preserves those results because they prevent repeated work and
make future packets more precise. A scoped obstruction can tell the next
Director what not to route. A freeze label can tell the next Formalizer,
Auditor, Refuter, or selector which path needs redesign before reuse.

The important discipline is scope. A failed draft/control packet can support:

- this packet did not discharge its stated burden;
- this selector route is underdetermined under the stated source tuple;
- this bridge attempt needs a missing primitive;
- this source-extension packet requires audit, stress, or human-gated
  adoption before downstream use.

It cannot support, by itself:

- AEther-Flow has failed globally;
- future source-extension work is impossible;
- ontology must be rejected;
- a benchmark is promoted or suspended;
- a Gate Chair verdict has been issued.

## Scoped Obstruction Versus Global No-Go

| Phrase type | Safe reading | Unsafe inflation |
| --- | --- | --- |
| Scoped obstruction | A specific route failed under stated assumptions, source tuple, and no-target-import rules. | The entire ontology is false. |
| Freeze label | A route should not be repeated without new payload, redesign, or gate action. | No future route can work. |
| Refuter stress result | A construction showed fragility, nonuniqueness, or dependency on missing data. | The project has no valid physics program. |
| Smuggling audit result | A packet passed or failed a hidden-import screen as written. | The object is adopted as canonical ontology. |
| Validator pass | The repository control checks passed. | Physics was proved. |

The burden map gives one explicit example:
`NDCL-RESP-LC-SELECTOR-UNDERDETERMINATION` is a candidate freeze label for the
current `Resp_lc` selector route. It means the current source tuple does not
determine response sign, normalization, or token semantics under no-target
import rules. It does not reject the entire ontology or prove future
source-extension impossibility.

## Gate Chair And Human-Gated Decisions

`registries/AGENT_ROLE_REGISTRY.csv` records `gate-chair@0.1.0` as a
human-gated role. It may create outputs and may promote claims only under its
protected gate status. It may not be executed automatically by a Documentation
Curator page, by a validator, or by ordinary generated output.

The same principle applies to ontology adoption, source-extension adoption,
benchmark promotion, and protected authority expansion. If the control system
says the next honest step needs a human gate, the correct summary is
"human-gated," not "done."

## Source-First Checklist

Before summarizing a failed or frozen line, inspect the source path and ask:

1. What exact burden was the packet trying to discharge?
2. Which source tuple, primitive, extension, or construction was tested?
3. Was the result a proposal, audit, stress test, completion, handoff, freeze,
   or gate?
4. Does the claim boundary forbid global no-go, ontology adoption, benchmark
   promotion, or generated-output authority?
5. Does the next route require a new payload, redesign, audit, refutation, or
   human-gated decision?

The safe answer is usually narrower than the tempting summary.

## Safe And Unsafe Summaries

Safe summary: AEther-Flow preserves proposals, audits, refutations, stress
tests, completions, handoffs, freeze labels, and human gates so each claim
stays scoped to its source evidence and authority boundary.

Unsafe summary: a frozen route proves the whole theory false, validators prove
physics, generated documentation can promote claims, or Gate Chair approval has
occurred without an explicit human-gated record.
